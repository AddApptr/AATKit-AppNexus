# AATKit-AppNexus

The AppNexus adapter for AATKit, as a Swift Package. Add it next to [AATKit](https://github.com/AddApptr/AATKit) when your app serves AppNexus demand; it pulls in the AppNexus SDK and nothing else.

* For more information about integration steps, please refer to the [integration documentation](https://docs.gravite.net/aatkit/ios/docs/documentation/aatkit/)

## Important Note
You have to add -ObjC in your build settings by following these steps:

* Click on the project navigator
* Click on your target and build settings
* Search for "other linker flags"
* Add "-ObjC"

## Where the binaries come from

The adapter itself is published by AATKit's release pipeline. The AppNexus SDK and its Open Measurement build are not: they are referenced straight from AppNexus's own Swift Package distribution, by URL and checksum.

Two reasons, both of which rule out the routes the other adapter packages take. Repackaging the CocoaPods copy lays the SDK's resources out differently from its SPM build, and creatives stop rendering at runtime. Depending on AppNexus's own package instead pins `GoogleMobileAds` to an exact version at package level, which Swift Package Manager enforces across the entire dependency graph — colliding with the version AATKit's AdMob adapter resolves. Only AppNexus's `ANGoogleAdapter` product needs Google, and AATKit does not use it, so that branch is dropped: this package has no Google dependency at all.

`Package.swift` is generated by `BuildScripts/SPM_scripts/BinariesGenerator` in the AATKit repository, from the routing table in `PackageManifest.swift`. Edit it there, not here.
